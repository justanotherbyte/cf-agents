---
title: "Build a typed Python Worker with crosswind-workers"
description: "Create a Python Worker with a Durable Object counter, generate its Env types with Wynd, run it locally and deploy it."
---

This guide builds a Worker that counts its requests in a
[Durable Object](https://developers.cloudflare.com/durable-objects/). By the
end, `curl` returns `{"greeting": "hello", "count": 1}`, and the count goes up
on every request.

## Prerequisites

- [`uv`](https://docs.astral.sh/uv/) 0.13.4 or later. Check with
  `uv --version`.
- Node.js, which provides `npx`. Wynd runs Wrangler through it.
- A Cloudflare account, for the deploy step only.

## 1. Create the project

Create a directory with a `src/` folder:

```sh
mkdir -p hello-worker/src
cd hello-worker
```

Declare `crosswind-workers` as a dependency:

```toml title="pyproject.toml"
[project]
name = "hello-worker"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["crosswind-workers"]
```

Wynd reads this list to choose the SDK. A project declares either
`crosswind-workers` or `workers-runtime-sdk`, never both.

## 2. Configure Wrangler

```jsonc title="wrangler.jsonc"
{
  "name": "hello-worker",
  "main": "src/entry.py",
  "compatibility_date": "2026-09-08",
  "compatibility_flags": ["python_workers"],
  "vars": { "GREETING": "hello" },
  "durable_objects": {
    "bindings": [{ "name": "COUNTER", "class_name": "Counter" }]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["Counter"] }]
}
```

The `python_workers` flag and the date pick the Python version. A date of
2026-09-08 or later runs Python 3.14. See
[Python targets](../wynd/commands.md#python-targets) for the other versions.

`main` must point into a subdirectory such as `src/`. Wynd copies that
directory when it deploys, and fails if `main` sits next to `wrangler.jsonc`.

`uvx wynd init` creates the same layout with the config written in Python, in
`cloudflare.config.py`. This guide uses `wrangler.jsonc` because no Wynd test
yet deploys a Durable Object declared in a Python config. See
[Configure a Worker in Python](../wynd/python-config.md).

## 3. Write the Worker

```python title="src/entry.py"
from env import Env
from workers import DurableObject, Request, Response, WorkerEntrypoint


class Counter(DurableObject[Env]):
    async def increment(self, by: int) -> int:
        count = (await self.ctx.storage.get("count") or 0) + by
        await self.ctx.storage.put("count", count)
        return count


class Default(WorkerEntrypoint[Env]):
    async def fetch(self, request: Request) -> Response:
        counter = self.env.COUNTER.get_by_name("global")
        count = await counter.increment(1)
        return Response.json({"greeting": self.env.GREETING, "count": count})
```

`Default` handles HTTP requests. `get_by_name("global")` returns a stub for
the Durable Object named `global`, and `counter.increment(1)` calls the method
on it over RPC.

> **Warning**
>
> Pass RPC arguments by position. `counter.increment(by=1)` type-checks, but
> the Durable Object receives one dictionary, `{"by": 1}`, in place of `by`.
> The request then fails with `TypeError: unsupported operand type(s) for +:
> 'int' and 'JsDict'`.

`env.py` doesn't exist yet. Wynd writes it in the next step.

## 4. Run it locally

```sh
uvx wynd dev
```

Wynd installs your packages for the Python target into `python_modules/`,
writes `src/env.py`, and starts Wrangler's dev server:

```text
wynd: wrote src/env.py
...
[wrangler:info] Ready on http://localhost:8787
```

In a second terminal:

```sh
curl http://localhost:8787/
```

```json
{"greeting": "hello", "count": 1}
```

Run it again and `count` is `2`.

The generated `src/env.py` types every binding in `wrangler.jsonc`:

```python title="src/env.py"
# Generated by wynd types. Do not edit.
from __future__ import annotations

from typing import TYPE_CHECKING, Protocol

from workers.bindings import DurableObjectNamespace

if TYPE_CHECKING:
    from entry import Counter


class Env(Protocol):
    COUNTER: DurableObjectNamespace[Counter]
    GREETING: str
```

Because `COUNTER` is `DurableObjectNamespace[Counter]`, a type checker reports
`counter.incremnt(1)` as an error. Commit `env.py`, and see
[Generate typed bindings](../wynd/types.md) for how Wynd builds it.

## 5. Set up your editor

Wynd doesn't create a virtual environment for your editor. Let uv create the
usual `.venv`:

```sh
uv sync
```

Point your editor at `.venv` if it doesn't find it. Then add Wynd's output to
`.gitignore`:

```text title=".gitignore"
.venv/
python_modules/
.wynd/
.wrangler/
```

Commit `pylock.toml`. It pins the package versions Wynd installs for the
Worker.

## 6. Deploy

Log in once, then deploy:

```sh
uvx wynd login
uvx wynd deploy
```

`wynd login` runs `wrangler login`. `wynd deploy` drops the vendored files
your Worker never imports, copies the rest into `.wynd/build/` and uploads
that copy. Wrangler prints the Worker's URL when it finishes.

To see the upload without sending it, run `uvx wynd deploy --dry-run`. Wynd
prints the bytes it removed before Wrangler's own output:

```text
wynd: python_modules is 127,013 bytes, 92,668 after pruning (34,345 fewer). Each file's decision is in .wynd/shake.txt.
```
