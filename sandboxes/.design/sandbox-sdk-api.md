# Sandbox SDK API

This table covers the public API of [`@cloudflare/sandbox`](https://developers.cloudflare.com/sandbox/reference/) 1.0.3 and how `crosswind-sandboxes` will port it to Python. The package installs as `crosswind-sandboxes` and imports as `sandboxes`, as in `from sandboxes import Files`. The deviations column records the choices the port made. An abort raises `SandboxAbortError`, and every error class derives from `SandboxError`. The package has no Python dependencies. It uses the JS objects of the runtime through the FFI, and the `workers` module that the Python Workers runtime provides. The choices follow the conventions of `containers-py` in [Coming from TypeScript](../docs/docs/containers/coming-from-typescript.md). "Open" marks a choice that still needs a test in Python Workers.

The logic flow column comes from the Cloudflare reference pages, the bundled `dist/index.mjs` of the npm package, and [`docs/shim-protocol.md`](https://github.com/cloudflare/sandbox-sdk/blob/main/docs/shim-protocol.md) in `cloudflare/sandbox-sdk`. "Shim" means `/usr/local/bin/sandbox-shim`. "Frame" means a shim control frame: a 10-byte header (`SBXF`, version `1`, kind, little-endian `u32` payload length) followed by the payload. Kind `0` is success, `1` is an errno and message, and `2` is data.

These deviations apply to every row, so the table does not repeat them:

- Names use `snake_case`, and option objects become keyword-only arguments.
- `AbortSignal` becomes an `asyncio.Event` passed as `abort=`. An event cannot cross RPC, so cancellation works only inside the Durable Object.
- Invalid values raise `ValueError`, and values of the wrong type raise `TypeError`. TypeScript raises `TypeError` for both.
- The SDK reuses the official shim binary unchanged and speaks protocol version 1. Each `crosswind-sandboxes` release pins the `cloudflare/sandbox` image tag it was tested against.

| Component | What it does | Logic flow | Deviations from official SDK |
| --- | --- | --- | --- |
| Package requirements | Lists what every class needs before it can run. | 1. The image must contain the shim, copied from `cloudflare/sandbox:<VERSION>`. The shim is a static `linux/amd64` binary.<br>2. The Worker needs `nodejs_compat`, because the package maps an errno to its name through `node:os`.<br>3. The container must be running. No class starts, stops, or monitors it. | The Python SDK needs no `nodejs_compat`. It maps an errno with the standard `errno` module instead. That module holds Pyodide's errno values, so the SDK needs a fixed table of Linux values. Open: whether the two sets match. |
| `sandbox-shim` | Runs one file, mount, or backup operation in the container and exits. | 1. The class calls `container.exec([SHIM, <command>, ...args])`, which starts one process per call.<br>2. The shim writes frames to stdout, or to stderr for `read`.<br>3. The class checks the magic bytes, the version, the payload length, and that no data follows the last frame. It then requires exit code `0`.<br>4. Anything malformed raises `SandboxProtocolError`. | Not ported. The Python SDK calls the same binary through `ctx.container.exec` over the FFI. |
| `Files(container)` | Reads and changes files in a running container. | The constructor stores the container. It needs only an object with `exec()`. | `Files(ctx.container)`. It also accepts any object with a compatible `exec`. |
| `FileOperationOptions` | Holds the options that every `Files` method accepts. | 1. `cwd` must be absolute. The class joins a relative path onto it and passes only absolute paths to the shim.<br>2. The class never passes `cwd` to `exec()`, so a missing `cwd` fails as `ENOENT` and not as a process that cannot start.<br>3. `user` must be `uid:gid`. It reaches `exec()` together with `signal`. | Keyword arguments: `cwd=`, `user=`, `abort=`. |
| `readFile(path)` | Streams a file's bytes. | 1. The class runs `read <path>`. Control frames arrive on stderr, and the raw file bytes arrive on stdout.<br>2. The first frame reports whether the file opened. An open error rejects with `SandboxFileError`.<br>3. On success, the class returns a `Response` whose body pulls from stdout, so backpressure reaches the shim.<br>4. A second frame after end of file reports the result. A failure errors the body.<br>5. The transport can deliver file bytes before the opening frame is complete, and hold the rest of the frame until stdout is read. So the class reads stdout ahead into a queue until the opening frame arrives, then reads it only as the body is read. 1.0.1 did not read ahead and could hang. | `read_file(path, *, cwd, user, abort) -> js.Response`. The Python code drives the stdout and stderr readers through the FFI. Open: the Python body must apply backpressure the way the JS body does. |
| `writeFile(path, content)` | Creates or truncates a file and streams content into it. | 1. The class turns `content` into a stream. A `str` becomes UTF-8 bytes.<br>2. It runs `write <path>` with stdin piped.<br>3. The shim sends an "opened" frame or an errno frame.<br>4. The class pumps the content into stdin and closes it.<br>5. The shim sends a final frame. An error in the source stream rejects with that error. | `write_file(path, content, *, cwd, user, abort)`. `content` is `str`, `bytes`, `bytearray`, `memoryview`, `AsyncIterable[bytes]`, or a JS `ReadableStream`. |
| `stat(path)` / `lstat(path)` | Returns metadata. `stat` follows a final symbolic link and `lstat` does not. | 1. The class runs `stat` or `lstat`, which returns one data frame of 45 bytes.<br>2. Byte 0 is the type. Bytes 1–8 are the size as `u64`. The next three `u32` fields are mode, uid, and gid. Three `i64` timestamps in milliseconds follow. | Returns a `SandboxFileStat` dataclass. `size` is an `int` (JS uses `bigint`), and the times are UTC `datetime` values (JS uses `Date`). To serialize a stat, call `dataclasses.asdict()` and convert the times to ISO strings before `json.dumps`. |
| `readDirectory(path)` | Lists the immediate entries of a directory. | 1. The class runs `read-directory`, which returns one data frame.<br>2. The payload starts with a `u32` count. Each entry is a type byte, a `u16` name length, and the name in UTF-8. A leading byte-order mark stays in the name.<br>3. A name that is not valid UTF-8 rejects the call with `EILSEQ`. | `read_directory(...) -> list[SandboxDirectoryEntry]`. |
| `mkdir(path, { recursive })` | Creates a directory. | The class runs `mkdir <path> [--recursive]`, which returns one success frame or one errno frame. | `mkdir(path, *, recursive=False, ...)`. |
| `rename(source, destination)` | Renames a path with Linux `rename` rules. | The class runs `rename <src> <dst>`, which returns one frame. A `SandboxFileError` sets both `path` and `destination`. | None beyond the shared deviations. |
| `remove(path, { recursive, force })` | Removes a file, a symbolic link, or a directory tree. | The class runs `remove <path> [--recursive] [--force]`, which returns one frame. | `remove(path, *, recursive=False, force=False, ...)`. |
| `SandboxFileStat`, `SandboxDirectoryEntry`, `SandboxFileType` | Hold the values that the stat and directory calls return. | The class decodes type bytes `0`–`6` as `file`, `directory`, `symlink`, `blockDevice`, `characterDevice`, `fifo`, and `socket`. | Frozen dataclasses. `SandboxFileType` is a `Literal` with `snake_case` values: `block_device` and `character_device`. |
| `SandboxFileError` | Reports a file operation that Linux rejected. | 1. An errno frame becomes `code`, `operation`, `path`, `destination`, and `detail`.<br>2. The message has the form `<operation> '<path>': <detail>`.<br>3. The thrown value is an `Error` whose `name` is `"SandboxFileError"`. The exported `SandboxFileError` is not a class but an object whose `is()` checks the name and fields, so it also recognizes errors returned through RPC. | An exception class, checked with `isinstance`. No `is()` helper. Open: how the error looks after it crosses JS RPC, which may need an `is_sandbox_file_error()` that checks `name`. |
| `SandboxProtocolError` | Reports a failed exchange with the shim, usually because the image tag and package version do not match. | The class raises it for a bad header, an unknown kind, truncated or trailing data, invalid UTF-8, or a nonzero exit after success. | An exception class. Same RPC question as `SandboxFileError`. |
| `S3Mount(container, gateway)` | Mounts an S3-compatible bucket or prefix with `s3fs`. | The constructor needs `exec` and `interceptOutboundHttp` on the container, and `ctx.exports.S3Gateway`. | `S3Mount(ctx.container, ctx.exports.S3Gateway)`. |
| `mount(request)` | Mounts a source at `mountPath`, or reuses or repairs a mount with the same settings. | 1. The class validates the request.<br>2. It runs `s3-mount mount <json>`. The shim replies with a route ID.<br>3. The class registers `interceptOutboundHttp("s3-<id>.sandbox.internal", gateway)` and writes one byte to stdin.<br>4. The shim starts `s3fs` against that host and replies with a JSON result. A different mount on the path raises `S3_MOUNT_CONFLICT`.<br>5. The class must call `mount()` before any `interceptAllOutboundHttp()`. | `mount(mount_path=, source=, access=, key_prefix=, s3fs_options=, abort=)`. `source` and its credentials are `TypedDict`s. |
| `inspect(mountPath)` | Reports the state of a path without changing it. | 1. The class waits for any `mount()` or `unmount()` in progress on the path.<br>2. It runs `s3-mount inspect <path>`. The shim reads the mount state and, for a `stale` or `managed` mount, sends one list request through the gateway.<br>3. The class returns `absent`, `unmanaged`, `incompatible`, `stale`, or `managed`. Only `stale` and `managed` include gateway status, and only `managed` includes FUSE status. | Returns a `TypedDict` that uses the same discriminant values. |
| `unmount(mountPath)` | Denies further storage requests, then unmounts. | 1. The class runs `s3-mount unmount <path>`. The shim replies with a route ID, or finishes at once when the path has no mount.<br>2. The class switches that route to deny and writes one byte.<br>3. The shim unmounts. A busy path raises `S3_MOUNT_BUSY` and requests stay denied. | None beyond the shared deviations. |
| `S3Gateway` | Checks and signs the container's S3 requests, so the container never sees the credentials. | 1. The gateway drops the container's `Authorization` header.<br>2. It allows only the object and list operations that `s3fs` uses, inside the bucket and prefix.<br>3. It signs each request with SigV4. For provider credentials, it first calls `GET https://credentials.sandbox.internal/`. | A Python `WorkerEntrypoint` exported from `sandboxes`, with SigV4 signing and the allow-list ported to Python. |
| `SandboxS3MountError` | Reports a failed mount operation. | The shim's JSON error `kind` (`busy`, `conflict`, `failed`, or `incompatible`) becomes `code` (`S3_MOUNT_BUSY`, `S3_MOUNT_CONFLICT`, `S3_MOUNT_FAILED`, or `S3_MOUNT_INCOMPATIBLE`). | An exception class. `code` is a `Literal`. |
| `DirectoryBackup(container, gateway, storage)` | Saves a directory to R2 and restores it. | The constructor validates `storage` (`binding` and an optional `prefix` that ends in `/`). | `DirectoryBackup(ctx.container, ctx.exports.DirectoryBackupGateway, binding="BACKUPS", prefix="")`. |
| `backup(options)` | Saves `dir` as one `tar+zstd` object and returns a record. | 1. The class runs `directory-backup backup <json>`.<br>2. The shim sends `{"kind":"locked"}` once it holds the backup lock for the container.<br>3. The class grants the gateway access to one object key and writes an acknowledgement byte.<br>4. The shim streams 16 MiB parts to `backups.sandbox.internal`, then reports the size and SHA-256.<br>5. The class denies the gateway access, then closes stdin to release the lock. This order keeps the cleanup from revoking a grant that the next operation already holds. On abort, it closes stdin and does not kill the shim, and the shim cleans up. | `backup(dir, *, name=None, exclude=(), gitignore=False, abort=None) -> DirectoryBackupRecord`. |
| `restore(record, { dir })` | Replaces a directory with a backup's contents. | 1. Steps 1 to 3 match `backup()`.<br>2. The shim downloads and extracts into a sibling directory, checks the size and SHA-256, then sends `{"kind":"verified"}`.<br>3. If no abort has arrived, the class writes a second acknowledgement byte, and the shim swaps the directory in with one rename. After that point, an abort no longer stops the swap.<br>4. The class denies the gateway access, then closes stdin, as in `backup()`. | `restore(record, *, dir=None, abort=None)`. |
| `delete(record)` | Deletes a backup object. | The Durable Object calls the gateway over RPC, which deletes the object. The call needs no running container and does not wait for the backup lock. | None beyond the shared deviations. |
| `intercept()` | Routes backup traffic to the gateway before a catch-all intercept is registered. | The class registers `interceptOutboundHttp("backups.sandbox.internal", gateway)` with a handler that refuses every request. A later operation replaces that handler. | None beyond the shared deviations. |
| `DirectoryBackupGateway` | Moves backup bytes between the container and R2. | 1. The gateway allows uploading parts of one object during a backup, and reading byte ranges of one object during a restore.<br>2. The Durable Object creates, completes, and aborts uploads, and deletes objects, through RPC calls to the gateway. | A Python `WorkerEntrypoint` that calls the JS R2 binding through the FFI. |
| `DirectoryBackupRecord` | Holds the plain object that `backup()` returns and that your class stores. | The record holds `id`, `dir`, `size`, an optional `name`, `sha256`, and `format: "tar+zstd/1"`. The object key is `<prefix><id>.tar.zst`. | A `TypedDict`, so `json.dumps` and Durable Object storage accept it unchanged. Records stay compatible with the JS SDK. |
| `SandboxBackupError` | Reports a missing, changed, or failed backup transfer. | The shim's error codes `notFound`, `integrity`, and `transfer` become `BACKUP_NOT_FOUND`, `BACKUP_INTEGRITY`, and `BACKUP_TRANSFER`. | An exception class. `code` is a `Literal`. |
| `ctx.container` | Starts the container and provides `exec`, ports, snapshots, timeouts, and intercepts. This is the runtime API, not the package. | Your Durable Object calls `start()` and `setInactivityTimeout()`, and the package classes call `exec()` and `interceptOutboundHttp()`. | Not wrapped. Call it through the FFI with `camelCase` names, as `containers-py` does. |
